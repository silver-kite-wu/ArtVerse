# 预约漫画生图：开发文档与范围

## 1. 文档状态

- 演进方向：统一的 Agent／生图定时任务中心方案见 [task-center-design.md](task-center-design.md)。本文保留一次性预约生图的当前实现边界；重复计划和统一任务中心尚未实现。
- 状态：首期后端已实现；接口、配置、调度选择和实际验证结果见 [scheduled-manga-generation-api.md](scheduled-manga-generation-api.md)。
- 目标：支持用户预约章节分镜生图，由协调 Agent 管控准备、派发、进度和失败恢复。
- 首期建议：持久化业务任务 + Spring 调度扫描 + AgentScope Agent 协调 + 有界生图 Worker。
- 本文是实现边界和验收依据。若实现时发现现有 API、领域模型或迁移与本文冲突，先保留本文边界，并在实现说明中指出差异。

## 2. 当前代码基线

实现前应重新核对这些文件，不能假定后续分支仍与本文编写时一致：

- `src/main/java/com/artverse/application/MangaGenerationService.java`：`generateMangaStream` 将任务放入 `mangaGenerationExecutor`，当前进程内通过 `activeJobs` 保存活动任务；章节分镜逐格生成，单格最多立即重试 3 次。
- `src/main/java/com/artverse/application/MangaGenerationJob.java`：SSE 订阅者和事件历史仅驻留内存。
- `src/main/java/com/artverse/config/TaskExecutorConfig.java`：漫画生图使用 JDK 虚拟线程执行器。
- `src/main/java/com/artverse/api/MangaGenerationController.java`：现有即时生成和单格重生成 API。
- `src/main/java/com/artverse/application/AgentOutboxService.java`、`AgentOutboxWorker.java`：PostgreSQL outbox、租约、fencing token 和重试用于 Agent 知识处理，不是图片生成队列。
- `src/main/java/com/artverse/config/AgentScopeConfig.java`：配置 Harness 对话压缩。`pom.xml` 使用 AgentScope 2.0.4；当前依赖没有 AgentScope Scheduler 扩展。

现有图片接口与预约接口职责不同：即时生图仍可使用当前 SSE 体验；预约请求应先返回持久化任务 ID，未来开始执行时再提供状态查询/实时进度。

## 3. 产品行为

### 必须支持

1. 登录用户可以直接创建预约任务；也可以在对话中提出定时需求，由对话 Agent 根据上下文自主判断是否调用受限的“创建预约生图任务”工具。
2. 首期支持一次性指定执行时间；用户也可以取消尚未开始的任务。未明确要求重复执行时，不得把一句定时需求默认为周期任务。
3. Agent 从用户请求中解析目标章节范围、待生成内容、时间、时区和模型偏好；时间或范围存在实质歧义时先向用户澄清，不得猜测后创建。
4. Agent 通过创建工具成功登记后，应返回任务 ID、解析后的本地时间及时区、章节数量、分格数量和任务状态。创建工具须以当前登录用户身份执行，用户 ID 不得由模型参数指定。
5. 创建时校验章节存在、用户权限、分镜可用、图片数量合法、模型配置有效，以及章节当前是否已有冲突的运行任务。
6. 任务在数据库中持久化，应用重启后仍能继续调度。
7. Agent 协调任务准备和逐格派发；生图 Worker 执行具体供应商 API 调用，不让 Agent 自行绕过服务层访问数据库、对象存储或密钥。
8. 每格独立记录状态和失败信息；允许重试失败分格，不要求重做成功分格。
9. 保留现有图片保存路径、生成记录、用户级模型配置、限流/幂等保护和内容授权检查。
10. 任务状态和错误对用户可解释；日志、指标和事件不得输出 API 密钥、原始凭据或不必要的长篇用户内容。

### 对话式创建语义

以“生成漫画请在凌晨 0 点开始完成当前未生成图片的章节”为例：

- 如果用户资料有时区，按该时区解释；否则使用产品配置的默认时区，并在创建摘要中明确展示。数据库时间统一存 UTC，同时保存解析用的时区 ID。
- “凌晨 0 点”默认表示最近一次未来的本地 00:00，且默认为一次性执行；如果用户表达的是每天/每周，则才创建重复计划。若“最近一次未来”与用户上下文不一致，先澄清。
- “当前未生成图片的章节”在创建时解析为明确的章节和缺失分格快照。默认不把创建后新增的章节自动纳入该任务；执行前再次检查图片是否已由其他任务生成，只派发仍缺失的分格。
- 对话 Agent 根据上下文自主判断用户是在询问定时功能，还是要求创建任务；后者才调用创建工具。Agent 将解析出的时间、时区、章节范围、执行策略等参数传给工具，工具在创建时校验并返回结果摘要。
- 用户已明确要求创建且参数足够明确时，Agent 可以直接调用创建工具，不强制增加预览或重复确认步骤。若范围过大、成本无法估算、配置不可用或时间存在实质歧义，Agent 再向用户确认或澄清。不能仅凭模型回复文本声称任务已创建，必须以工具返回的持久化任务 ID 为准。

### 首期明确不做

- 不引入 RabbitMQ、Kafka 等新消息中间件。先复用 PostgreSQL 持久化任务及现有数据库认领模式；未来吞吐量证明确有需要时再评估 MQ。
- 不做通用 Cron/工作流平台，也不让 Agent 常驻等待或 `sleep` 到预约时间。
- 不自动抓取/推断各模型供应商实时价格，不承诺某时段一定半价。
- 不改变现有即时生图 API 的语义或前端流程；除非实现任务明确包含兼容适配。
- 不在数据库中保存明文 API Key，不长期保存会过期的签名 URL。
- 不在首期自行实现链表、小顶堆或时间轮。
- 不在缺少供应商支持时承诺跨网络故障的“严格 exactly-once”生图。

## 4. 定时与扫描策略

调度扫描是唤醒机制，数据库是任务真相；不要把未来任务提前全部加载进 JVM 内存。

首期默认参数建议外置配置：

| 用途 | 初始间隔/窗口 | 查询与处理 |
| --- | --- | --- |
| 到期触发 | 首选调度器的一次性触发 | 触发后唤醒协调 Agent；应用层仍须从数据库校验任务状态并原子认领，不能仅依赖调度器回调。 |
| 执行前预热 | 默认提前 5 分钟 | 通过另一个一次性触发唤醒协调 Agent 准备上下文；可配置，并根据实测准备耗时 P95 加安全余量调整。预热不调用计费生图 API。 |
| 数据库轮询回退 | 派发每 5 秒、预热每 30 秒 | 仅在选用的调度 API 不支持所需的一次性触发/持久化语义时启用；有限批量认领到期任务，不把未来任务全部载入 JVM。 |

优先通过 AgentScope `AgentScheduler` API 注册一次性触发，由其后端调度器在预热/执行时间唤醒协调 Agent。触发注册和业务任务创建必须有幂等关联；若注册成功但应用写库失败，或反向失败，应有补偿/对账策略。数据库查询应由状态与时间索引支持，并采用 `FOR UPDATE SKIP LOCKED` 或等效的原子租约认领，以支持多实例。无论采用何种触发机制，都不能让调度器注册记录成为业务任务的唯一真相。

AgentScope Java 2.0.4 的公开文档列出 CRON 和固定频率调度，但没有明确展示“指定绝对时间的一次性触发”示例。实现会话必须先检查当前依赖版本的真实 API 与持久化/取消能力；如果没有一次性任务能力，使用 Quartz 的一次性 Trigger（通过适配层）或本文定义的数据库轮询回退，不能把一次性请求伪装成 CRON 任务。

如果用户选择的是一个折扣时间窗而非具体开始时刻，应将“开始时间”和“完成期限”作为明确的业务字段。按历史生图耗时估算启动时机并留出重试余量；无法确认实际价格规则时，只能描述为错峰调度。

## 5. Agent 与组件职责

建议新增章节级协调 Agent（命名可按现有风格调整，如 `MangaRenderCoordinatorAgent`），但 Agent 只在生命周期事件触发时短暂运行，不常驻占用线程。

### 意图识别与提示词边界

- 是否创建由对话 Agent 根据上下文判断。不要在 Java 服务中另写关键词/正则分类器来替代模型决定是否调用工具。
- 给 Agent 提供简洁、准确的工具名称、描述和参数 Schema，让模型能理解何时创建预约、需要哪些参数及成功/失败返回值；不通过冗长固定提示词穷举所有表达方式。
- 用简短的系统指令说明基本职责即可：遵循用户意图、必要时澄清、工具成功后报告结果。定时范围解析、授权、参数合法性、幂等、任务状态转换和费用保护必须在应用服务/工具实现中校验，不能依赖提示词保证。
- 工具可以直接创建清晰无歧义的用户请求。只读预览工具是可选能力，用于高成本、范围不清或需要展示估算的场景；不要求 Agent 每次都先预览。
- 用户是在询问“能不能定时”时，Agent 应先回答问题，不应创建任务；用户表达了“请安排/定时生成”等执行意图时，Agent 可自主决定调用创建工具。

### 协调 Agent 可以

- 读取已认领任务的不可变输入快照和当前任务状态。
- 根据自然语言上下文判断是否存在创建预约的执行意图；需要创建时通过受限工具登记任务，遇到歧义或需要用户决定的高成本范围时先澄清。
- 在授权工具范围内准备/校验章节上下文、检索需要的故事知识、构建分格提示词，并生成准备快照及 hash。
- 通过应用服务拆分/派发逐格任务、检查状态、汇总结果、请求对可重试错误进行再次派发。
- 将状态转换请求交给领域服务验证；工具需带任务 ID、用户/租约上下文和幂等键。

### 协调 Agent 不可以

- 直接读写数据库、文件系统、MinIO 或 Redis；不得绕过现有服务和授权检查。
- 访问或回显明文 API Key；模型凭据须在 Worker 发出请求时由后端配置服务解析。
- 自行改变任务所属用户、章节、模型配置或授权边界。
- 将用户未表达的重复周期、目标章节范围、时区或执行时间自行补成事实；存在歧义时必须澄清。
- 无限重试、无限并发、重复扣费，或在模型输出中自定新的生图目标。
- 将模型自然语言回复作为任务成功的唯一依据；成功必须由持久化业务状态和图片结果确认。

### 确定性组件职责

- **对话 Agent：**自主判断用户意图；用户要求创建预约时，调用“创建预约生图任务”工具，将表达转成结构化参数。不用冗长固定提示词或硬编码意图分类器代替 Agent 判断。
- **调度 API 适配器：**优先通过 AgentScope `AgentScheduler` 注册预热和执行的一次性唤醒；若所用版本不支持一次性触发，则使用 Quartz 一次性 Trigger 或数据库轮询回退。
- **任务服务与仓储：**鉴权、状态机、乐观/租约并发控制、幂等、取消与审计。
- **章节协调 Agent：**被调度器唤醒后，针对已认领任务执行有限步骤的预热、派发协调和结果汇总。
- **生图 Worker：**调用供应商 API、上传结果、更新分格状态、清理临时文件。
- **AgentScope Scheduler 扩展：**作为首选 Agent 定时触发 API 评估和接入；若当前版本不支持所需的一次性定时语义，按上文选用 Quartz 一次性 Trigger 或数据库轮询回退。无论哪种方式，都保留数据库任务状态和执行幂等。

## 6. 建议状态模型

章节任务状态：

```text
SCHEDULED -> PREPARING -> READY -> RUNNING -> SUCCEEDED
                    |        |         |----> PARTIAL_FAILED
                    |        |         |----> FAILED
                    |        |         |----> CANCELLED（仅取消尚未开始的分格）
                    |        |----> STALE_REQUIRES_CONFIRMATION
                    |----> FAILED / CANCELLED
```

分格任务状态：

```text
PENDING -> READY -> RUNNING -> SUCCEEDED
                         |----> RETRY_WAIT -> READY
                         |----> FAILED
                         |----> CANCELLED
```

最终命名可调整，但必须区分章节聚合状态和每格状态，且状态转换须集中校验。重复扫描同一任务不得重复启动同一代任务。

## 7. 数据与一致性要求

建议模型至少保存：

- 任务 ID、用户 ID、故事/章节 ID、章节版本、状态、创建/预约/准备/开始/完成时间。
- 模型配置引用（ID/版本），不得保存明文凭据；执行时重新验证用户仍有可用配置。
- 输入快照策略及其版本/hash：故事/章节/分镜、角色资料、素材对象键、生成参数、模型和提示词版本。
- 单格任务的分镜序号、提示词快照或安全可重建引用、状态、尝试次数、下一重试时间、结果对象键、错误分类。
- 租约持有者、租约到期时间、fencing/version 字段，以及可排查但不含秘密的错误信息。

快照策略必须明确：预约时固定章节版本，或用户选择执行前使用最新版本。首期推荐预约时记录章节和分镜版本；执行前检测版本变化，默认转入 `STALE_REQUIRES_CONFIRMATION`，不得静默用新内容替换用户预约内容。

外部生图 API 可能不支持幂等键。Worker 在“供应商已成功但应用尚未记录结果”时可能存在结果不确定的窗口；需在设计中说明恢复策略，不能把至少一次派发包装成 exactly-once。若供应商支持幂等键，使用稳定的逐格调用键；否则对不确定状态进入可审查/人工重试状态，避免自动重复付费。

## 8. 重试、并发与取消边界

- 分格独立重试；退避采用可配置的指数退避并加入 jitter，尊重供应商 `Retry-After`。
- 默认最大尝试次数建议 3 次，与现有逐格实现保持接近；配置应区分可重试错误（超时、429、部分 5xx）和永久错误（参数/权限错误）。
- 超过上限进入 `FAILED`，保留错误分类和手动重试入口所需信息；不要求引入独立 DLQ 服务。
- 生图并发受全局、用户、供应商/模型三层配置限制；首期可先实现全局及供应商级有界并发。
- 用户取消只影响尚未发送给供应商的分格；已发出的 HTTP 调用是否可取消取决于客户端/供应商支持。取消须幂等。
- 超时、应用重启、租约过期时允许其他实例接管；旧持有者的迟到结果不能覆盖新执行结果，需校验 fencing token/版本。

## 9. API/前端边界

如果任务实现包含 API，保持现有路由约定，并新增独立预约资源，而非让 SSE 请求等待到未来时间：

- 创建预约：返回任务 ID、当前状态、预约时间和可解释的校验结果。
- 查询任务：返回章节聚合状态和逐格进度，按用户权限过滤。
- 取消预约：仅允许对未开始/可取消状态执行。
- 运行期间进度：复用或扩展现有 SSE 事件协议；断线后仍可从持久化状态恢复。
- Agent 工具：提供“创建预约生图任务”受限工具；可另提供只读预览工具处理模糊或高成本请求。用户身份从可信运行上下文注入；模型只能提供用户表达的需求字段，不能传入任意 userId 或绕过服务层校验。创建工具由应用服务落库并调用调度 API 适配器，不允许模型直接持有调度器实例或访问底层数据库。

默认实现范围为后端 API、Agent 工具和任务生命周期。若实现会话未明确要求前端页面，则不要顺手重做图片生成页面；至少提供可调用 API、Agent 工具契约和响应格式。

## 10. 验收条件

实现完成后需给出以下证据（由实现会话实际执行并报告）：

1. 预约任务、逐格状态、索引和新状态均通过新增 Flyway migration 建立；旧 migration 不被修改。
2. 同一预约请求幂等；两个应用实例并发扫描时，同一任务/分格不会被同时有效认领。
3. 重启后预约仍存在并能恢复；取消、超时、租约到期和 stale 章节版本路径均可预测处理。
4. 逐格失败不会阻断其他分格；可重试与不可重试错误分类有效，达到上限后停止自动重试。
5. 生成成功的结果被持久化并能查询；不确定的外部调用不会被无条件自动重复收费。
6. Worker 的并发受限；认证、章节归属、模型配置和对象存储权限沿用现有安全边界。
7. Agent 仅通过受限工具操作任务；Agent 输出错误、超时或不可用时，任务状态仍保持可恢复，不产生未授权生图。
8. 预约 API 与现有即时生图/SSE 行为兼容；文档列出配置项、API 契约、迁移、测试/编译结果和任何未实现部分。

## 11. 实现会话的建议步骤

1. 先检查当前 `git status`、相关 Java 类、Flyway migration、图片 API DTO/前端调用和已有测试；保留工作区中其他改动。
2. 对照本文和代码，列出小型实现计划及需要新增/修改的文件。
3. 先实现任务领域模型、迁移、状态机和持久化认领；再接入调度器、协调 Agent 和逐格 Worker；最后接入 API。
4. 为状态转换、幂等认领、重试分类和权限边界补聚焦测试。
5. 按 `ArtVerse/AGENTS.md` 执行后端检查。结束时说明已实现项、未实现项、迁移/API/配置变化、执行过的验证及结果。
